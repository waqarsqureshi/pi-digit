Raspberry Pi Digital Twin Emulator

Comprehensive manual for deploying, programming, and monitoring the hardware emulator on Raspberry Pi 4, Pi 5, Pi 400, and compatible single-board computers.

A. Introduction

1. Purpose of the Digital Twin Emulator

The Raspberry Pi Digital Twin Emulator is an educational and industrial engineering system designed to bridge physical hardware interfaces with high-fidelity, real-time web monitoring and execution tools.

Unlike pure browser mockups, this application is engineered to run on a host Raspberry Pi running Raspberry Pi OS (Debian Linux). It binds directly to native Linux kernel subsystems:

  • Linux Framebuffer (/dev/fb1): Provides direct 16-bit RGB565 and 24-bit RGB pixel rendering for the Sense HAT 8×8 LED matrix.
  • Linux I2C Bus Subsystem (/dev/i2c-1): Interfaces with the STMicroelectronics HTS221 temperature/humidity sensor and LPS25H barometric pressure sensor.
  • BCM2835 / RP1 GPIO Memory Interface (/dev/gpiomem): Directly maps physical 40-pin GPIO registers with zero-latency input/output states and PWM frequency timers.
  • Input Event Subsystem (/dev/input/event*): Reads the Sense HAT 5-way joystick (Up, Down, Left, Right, Enter/Click) via the ATtiny88 microcontroller.

2. Principal Capabilities

The emulator operates continuously on port 3000 of your Raspberry Pi, serving an interactive digital twin console that provides:

  • Real-time Bilateral Hardware Sync: Python and C programs executed on the Pi update the physical hardware and mirror their states instantly to the web UI via WebSockets.
  • Live Code Studio: Multi-tab editor supporting Python 3 and C (GCC C99), with instant compilation, execution, process termination, and standard input/output streaming.
  • Virtual Hardware Fallback: If sensors are unlinked or you are testing logic prior to attaching a HAT, the emulator keeps your scripts running without throwing unhandled exceptions.
  • Live Diagnostics Console: Scans device tree overlays, permissions, framebuffer devices, and I2C addresses, outputting copyable troubleshooting commands.

3. Hardware & Software Requirements

¤
Verified Requirements: Raspberry Pi 4 Model B (any RAM revision) or Raspberry Pi 5 running Raspberry Pi OS (Bookworm 64-bit or Bullseye) with Node.js 18+ and Python 3.9+.

B. Getting Started

1. Prerequisites

Before installing, ensure your Raspberry Pi has internet access and standard build utilities:

Terminal (Raspberry Pi OS) 
# Update package repositories
sudo apt update && sudo apt install -y git curl build-essential python3 python3-pip

2. Obtaining the Project from GitHub

Clone the official repository to your Pi's home directory:

Terminal 
git clone https://github.com/waqarsqureshi/pi-digit.git
cd pi-digit

3. Step-by-Step Installation

The repository includes a dedicated emulator/install.sh script that configures group permissions (I2C, GPIO, input, video), installs dependencies, and sets up the systemd service:

Terminal 
# Make installer executable and run
chmod +x emulator/install.sh
bash emulator/install.sh

View emulator/install.sh directly on GitHub →

!
Reboot Recommended: If this is your first time enabling I2C or the Sense HAT device tree overlay, run sudo reboot after the installer finishes so the Linux kernel can bind /dev/fb1.

4. Launching the Emulator & Connecting

After rebooting, verify your working directory before starting the daemon:

Terminal 
# 1. Switch to the pi-digit directory (check pwd)
cd ~/pi-digit
pwd
# Expected output: /home/<user>/pi-digit

# 2. Start the daemon server
npm start

On startup, the daemon inspects network interfaces and outputs your live connection URL:

  • Remote Network Browser (LAN): http://<your-pi-ip>:3000/emulator/ (detected automatically from Wi-Fi or Ethernet)
  • Local Pi Browser: http://127.0.0.1:3000/emulator/ or http://localhost:3000/emulator/
  • Offline / Standby: If not connected to a network, the server automatically defaults to the local loopback (127.0.0.1:3000).

5. Troubleshooting Guide

Common issues encountered on Raspberry Pi OS and their resolutions:

Issue A: "No module named 'sense_hat'"

Install the system sense-hat driver package:

Fix Command 
sudo apt install -y python3-sense-hat python3-smbus

Issue B: "Permission denied on /dev/fb1 or /dev/i2c-1"

Add your user account (usually pi or your chosen username) to hardware groups:

Fix Command 
sudo usermod -a -G i2c,gpio,input,video $USER
newgrp i2c

Issue C: "/dev/fb1 not found"

Enable the Sense HAT overlay in your boot configuration file:

Raspberry Pi OS Bookworm / Bullseye 
# Check /boot/firmware/config.txt or /boot/config.txt
# Ensure the following lines are present:
dtparam=i2c_arm=on
dtoverlay=rpi-sense

C. How to Write and Run Code

1. Integrated Code Studio

The emulator interface includes a built-in Code Studio on the left half of the screen. You can:

  • Switch between predefined template tabs (Python LED animations, sensor polling, C GPIO triggers, LCD messages).
  • Write custom Python 3 or C99 code directly in the browser editor.
  • Click Run Script to execute the code with a configurable timeout.
  • View real-time standard output (stdout), errors (stderr), and exit codes streamed to the terminal log.

2. Python Sense HAT API Examples

The emulator supports the standard Raspberry Pi Foundation sense_hat library alongside the unified py_twin library located in src/. Code written using from py_twin import SenseHat, GPIO, PWM, LCD, from sense_hat import SenseHat, or from pi_twin import SenseHat runs without modification.

Example 1: Displaying Temperature & Humidity

read_sensors.py 
from sense_hat import SenseHat
import time

sense = SenseHat()

# Read calibrated sensors
temp = sense.get_temperature()
humidity = sense.get_humidity()
pressure = sense.get_pressure()

print(f"Temperature: {temp:.2f} °C")
print(f"Humidity:    {humidity:.2f} %")
print(f"Pressure:    {pressure:.2f} hPa")

# Scroll temperature across the 8x8 LED matrix
sense.show_message(f"{temp:.1f}C", text_colour=[255, 120, 0], scroll_speed=0.08)

Example 2: 8×8 RGB LED Matrix Pixel Manipulation

matrix_rainbow.py 
from sense_hat import SenseHat
import time

sense = SenseHat()
sense.clear()

# Draw diagonal gradient
for x in range(8):
    for y in range(8):
        r = int((x / 7.0) * 255)
        g = int((y / 7.0) * 255)
        b = int(((x + y) / 14.0) * 255)
        sense.set_pixel(x, y, r, g, b)

time.sleep(3)
sense.clear()

3. C & GPIO Programming

You can write C programs to interact with the 40-pin GPIO header. The emulator backend compiles C scripts using gcc -O2 -Wall and executes them in an isolated subprocess:

gpio_blink.c 
#include <stdio.h>
#include <unistd.h>
#include "pi_twin.h"

int main(void) {
    printf("Initializing GPIO Pin 17 Output...\n");
    pi_gpio_set_mode(17, PI_OUTPUT);

    for (int i = 0; i < 5; i++) {
        printf("LED ON (Pin 17 HIGH)\n");
        pi_gpio_write(17, PI_HIGH);
        usleep(300000); // 300 ms

        printf("LED OFF (Pin 17 LOW)\n");
        pi_gpio_write(17, PI_LOW);
        usleep(300000);
    }

    printf("Cycle completed successfully.\n");
    return 0;
}

4. Shell Scripts & Terminal Execution

The embedded web terminal at the bottom of the Code Studio supports interactive shell commands:

  • diagnose — Runs an instant hardware check across all buses.
  • blink-test — Flashes the physical 8×8 LED matrix to verify /dev/fb1.
  • i2c-check — Probes I2C devices at addresses 0x5F, 0x5C, and 0x6A.
  • fb-check — Inspects available framebuffer nodes.
  • gpio readall — Prints a table of physical pin states.

5. Physical vs. Emulated Execution

✓
Transparent Fallback: If a Sense HAT is physically plugged into the Pi, your code writes directly to /dev/fb1 and queries the real I2C sensors. If the HAT is not present, the emulator's Python wrapper seamlessly channels values into the digital twin memory buffer so your program runs cleanly without crashing.

D. Emulator Architecture & Features

1. Internal Codebase Structure & Data Flow

The Pi-Digit digital twin operates across three architectural layers: the physical Linux kernel space, a persistent Python 3 hardware daemon, a TypeScript Node.js/Express IPC server, and a high-performance React web twin:

2. Sense HAT 8×8 LED Matrix & /dev/fb1

The Sense HAT LED matrix is driven by an Atmel ATtiny88 microcontroller communicating via I2C with the Raspberry Pi's Broadcom SoC. In Linux, the rpi-sense-fb kernel driver creates a framebuffer node at /dev/fb1 with 64 pixels formatted as 16-bit RGB565 words (5 bits Red, 6 bits Green, 5 bits Blue):

Framebuffer Technical Specification 
Device Node    : /dev/fb1
Resolution     : 8 x 8 pixels (64 total)
Color Format   : RGB565 (2 bytes per pixel, 128 bytes total frame)
Bit Allocation : R[15:11], G[10:5], B[4:0]
Gamma Table    : 32-level nonlinear intensity curve
Memory Access  : Direct binary stream seek(y * 8 + x) * 2; write(rgb565)

3. I2C Sensor Bus Architecture & Temperature Calibration

The Sense HAT multiplexes three primary sensor chips on I2C Bus 1 (/dev/i2c-1):

  • HTS221 (0x5F): Capacitive digital relative humidity and temperature sensor. Raw temperature output reflects the warm Raspberry Pi 4 CPU directly beneath the HAT (~50–56°C / ~132°F). The daemon applies continuous CPU compensation (T_ambient = T_raw - (T_cpu / 2.0) or T_raw - 25.5°C) to display realistic ambient room temperature (~21–25°C).
  • LPS25H (0x5C): Piezoresistive absolute pressure sensor operating from 260 to 1260 hPa. Also provides secondary internal temperature readings.
  • LSM9DS1 (0x6A & 0x1C): 3D accelerometer, 3D gyroscope, and 3D magnetometer producing 9 degrees of freedom inertial telemetry.

4. 5-Way Joystick & Linux evdev Subsystem

The 5-way navigation switch on the Sense HAT is exposed in the Linux kernel as an evdev input event device (typically /dev/input/event* under the device name Raspberry Pi Sense HAT Joystick):

  • Keycodes: KEY_UP (103), KEY_DOWN (108), KEY_LEFT (105), KEY_RIGHT (106), and KEY_ENTER (28) / KEY_OK (352) (Middle Click).
  • Action Events: Value 1 (Press / Pressed), Value 2 (Hold / Held), Value 0 (Release / Released).
  • Both the physical hardware daemon and the Web UI digital twin support the complete press-hold-release lifecycle with visual indicator badges and event queues so no quick clicks or holds are dropped.

5. 16×2 HD44780 Alphanumeric LCD (Hardware Distinction Note)

!
Hardware Architecture Notice: The physical Raspberry Pi Sense HAT contains the 8×8 RGB LED Matrix, but does not have an onboard LCD screen. The LCD in this platform emulates an external industry-standard HD44780 character LCD display interfaced via a PCF8574 I2C expander on the I2C-1 bus (address 0x27 or 0x3F). This illustrates how external embedded alphanumeric displays operate in robotics, test benches, and industrial instrumentation alongside the Sense HAT.

6. Real-Time Camera Pipeline & Edge Detection

The digital twin supports Raspberry Pi Camera Module 2/3 (via CSI-2 / libcamera) and USB UVC webcams (via V4L2 /dev/video0). Frames are streamed to the emulator in a dedicated pop-out window featuring client-side real-time 3×3 Sobel convolution edge detection:

Sobel Edge Detection Convolution Kernel 
Horizontal Kernel (Gx):           Vertical Kernel (Gy):
[ -1  0  +1 ]                     [ -1  -2  -1 ]
[ -2  0  +2 ]                     [  0   0   0 ]
[ -1  0  +1 ]                     [ +1  +2  +1 ]

Gradient Magnitude: |G| = sqrt(Gx^2 + Gy^2)
Real-time controls: Adjustable edge threshold, grayscale gradient, and inversion filter.

7. Daemon IPC & WebSockets

The system architecture separates hardware polling from frontend presentation:

  1. A persistent Python hardware daemon (scripts/hardware_daemon.py) samples /dev/fb1, evdev, and I2C every 60ms, writing a structured state snapshot to /tmp/pi_sense_hardware.json.
  2. The Node.js server (server.ts) monitors this file and emits delta updates over a WebSocket stream (ws://localhost:3000/ws).
  3. The React frontend updates the UI smoothly at 60 FPS, maintaining minimal CPU load on the Raspberry Pi host.

E. Installation, Updates & Uninstallation

1. Automated Installation Script

The standard installation command downloads and configures all components:

Terminal 
curl -sSL https://raw.githubusercontent.com/waqarsqureshi/pi-digit/main/emulator/install.sh | bash

Inspect installer source on GitHub: github.com/waqarsqureshi/pi-digit/blob/main/emulator/install.sh →

2. Running as a Persistent Systemd Service

To make the emulator start automatically when your Raspberry Pi boots up, configure a systemd service:

Create /etc/systemd/system/pi-twin.service 
sudo tee /etc/systemd/system/pi-twin.service > /dev/null << 'EOF'
[Unit]
Description=Raspberry Pi Digital Twin Emulator Daemon
After=network.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/pi-digit
ExecStart=/usr/bin/npm start
Restart=on-failure
RestartSec=5
Environment=PORT=3000

[Install]
WantedBy=multi-user.target
EOF

# Enable and start the service
sudo systemctl daemon-reload
sudo systemctl enable pi-twin.service
sudo systemctl start pi-twin.service

3. Updating the Emulator

To pull the latest enhancements and bug fixes from GitHub:

Terminal 
cd ~/pi-digit
git pull origin main
npm install --production
npm run build

4. Clean Uninstallation

If you wish to remove the emulator from your Raspberry Pi:

Terminal 
# Stop and disable systemd service if installed
sudo systemctl stop pi-twin.service 2>/dev/null
sudo systemctl disable pi-twin.service 2>/dev/null
sudo rm -f /etc/systemd/system/pi-twin.service
sudo systemctl daemon-reload

# Remove project directory
rm -rf ~/pi-digit
